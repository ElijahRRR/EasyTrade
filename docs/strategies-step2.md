# 第二步策略说明（step 2）

> 第二步的目标：找到**样本外**也赚钱、账户整体回撤 ≤ 8%、杠杆 ≤ 5 倍的策略，并且尽量避免过拟合。
> 第一步的三个移植策略见 [`strategies.md`](strategies.md)。
>
> 本文档分两大部分：
> - [趋势类](#趋势类)：`DonchianTrend`、`TsmomTrend`、`BigTrendBoth`，以及所有新策略共用的风控 `easytrade_risk.py`
> - [非趋势类](#非趋势类)：`RangeMeanReversion`、`VolSqueezeBreakout`、`FundingContrarian`
>
> **怎么验证以 `make research` 为准**（README「第 2 步：策略研究」）：它自动按数据切分训练段（前约 2/3）、
> 样本外（最后约 1/3）和走步验证，调参只用训练窗口，最后出中文排名表。
> 下面各节里手写的 `--timerange 20240101-20250701` 之类的命令只是"单独抽查某一段"的例子，
> 日期和 `make research` 的自动切分不一定相同，**判断能不能用，看 `make research` 的结果**。

## 趋势类

> 对应 freqtrade 2026.10，最后更新：2026-11-06。代码在 `user_data/strategies/`：
> `DonchianTrend.py`、`TsmomTrend.py`、`BigTrendBoth.py`，共用风控模块 `easytrade_risk.py`。
> 这三个策略**还没有在真实 OKX 数据上回测过**，下面的"为什么可能有效"是思路，不是结果。
> 合成数据只用来确认"能跑、不报错"，那上面的收益和回撤数字没有任何意义。

### 趋势类 0. 一页看懂

| 策略类名 | 一句话逻辑 | 周期 | 方向 | 初始止损 | 出场 | 可调参数 |
|---|---|---|---|---|---|---|
| `DonchianTrend` | 收盘突破过去 55 天最高价做多（跌破最低价做空），只顺着日线 EMA200 的方向做 | 1d（也可 4h） | 多 + 空 | 2 × ATR20 | 价格碰到最近 20 天的最低价（做空：最高价），这条线会跟着趋势往上挪 | 3 个 |
| `TsmomTrend` | 过去 20 / 40 / 80 天"涨得明显"就做多、"跌得明显"就做空，动量消失就平 | 1d | 多 + 空 | 3 × ATR20 | 动量分数回到 0 | 3 个 |
| `BigTrendBoth` | BigTrendShort 的信号原样保留，再加上镜像的做多信号；只在 BTC 牛市做多、熊市做空 | 1d | 多 + 空 | 3 × ATR14 | 止损 / 持满 13 天 | 2 个 |

三个策略的共同点：

- **多空双向**。11 月 OKX 回测已经说明，6 月那几个"只做空"的优势大部分是熊市带来的（beta），换了行情就失效。
  趋势跟踪不预测方向，涨就跟涨、跌就跟跌。
- **参数很少，而且范围很窄**（每个策略 2 到 3 个可调参数），默认值全部用教科书上的经典值，不是在这份数据上挑出来的。
- **风控完全一样**，都由 `easytrade_risk.py` 负责（见下一节）：每笔最多亏 0.5%，所有持仓加起来最多亏 3%，杠杆 2 倍。

### 趋势类 1. 共用风控（`easytrade_risk.py`）

这是第二步所有新策略共用的"风控模块"（不是策略）。写法是 `class 策略名(EasyTradeRiskMixin, IStrategy)`。
其他类型的第二步策略也用它，所以规则对所有新策略都一样。

#### 1.1 杠杆

- 实际杠杆 = min(`max_leverage_param`（默认 **2**），交易所对这个币允许的最大杠杆，**5**)，并且至少 1 倍。5 倍上限写死在代码里。
- 杠杆**不决定**一笔亏多少，只决定占用多少保证金、离强平价多远。亏多少由下面的仓位公式决定。

#### 1.2 每笔开多少（按止损距离定仓）

```
风险金额 = 总资金 × 0.5%（risk_per_trade）
名义仓位 = 风险金额 ÷ (止损距离 + 0.2% 手续费滑点缓冲)
保证金   = 名义仓位 ÷ 杠杆
```

- **总资金** = freqtrade 口径：钱包 × 95%（`tradable_balance_ratio`），含已占用的保证金，随盈亏变化。资金变成 10000 USDT 时自动放大，不用改代码。
- 止损距离不到 1% 时按 1% 算（防止仓位太大）；止损最远放到入场价的 25%（再远就截到 25%，仓位也按 25% 算）；
  杠杆高时再收紧到 0.8 ÷ 杠杆（5 倍时 16%），保证止损永远在强平价之前。
- 名义仓位不超过 1 倍总资金；保证金不超过 freqtrade 的建议仓位（可用资金 ÷ `max_open_trades`）。
- 算不出有效止损、或者出任何错，**一律不开仓**（不会回退成满仓）。

**1000 USDT 账户的例子**（总资金按 950 算，风险金额 4.75 USDT，2 倍杠杆）：

| 情况 | 止损距离 | 名义仓位 | 保证金 | 打到止损大约亏 |
|---|---|---|---|---|
| BTC 日线，ATR 约 3%，Donchian 2 × ATR | 6% | 77 U | 38 U | 4.75 U（0.5%） |
| 山寨币日线，ATR 约 6%，TSMOM 3 × ATR | 18% | 26 U | 13 U | 4.75 U |
| 山寨币日线，ATR 约 9%，3 × ATR = 27% | 截到 25% | 19 U | 9.5 U | 4.75 U |

> **1000 USDT 时仓位很小**。有的合约单笔最小下单量比这还大（例如币安 BTCUSDT 永续的最小名义金额较高，约 100 USDT，以交易所当时的规则为准），
> 这时 freqtrade 会把这一笔放大到最小下单量（最多放大 30%），再不够就**不开这一笔**。所以小资金时交易数会比回测少一点。

#### 1.3 组合热度上限（3%）

"热度" = 如果现在所有持仓同时打到各自的止损，**从现在的价格算**还会亏多少钱。规则：开新仓前，

```
已有热度 + 这一笔的风险 ≤ 总资金 × 3%（max_portfolio_risk）
```

- 剩余额度不够一整笔时，按剩余额度缩小这一笔；剩余额度连一笔的 25% 都不到，就不开。
- 为什么要它：币和币之间高度相关，一次急跌（或逼空）可能让所有多单（或空单）同时打到止损。热度上限就是"最坏情况下一起亏多少"。
- 盈利的单子如果止损还没跟上来，离止损的距离变大，热度也会变大（因为那部分浮盈也可能吐回去），这时会少开新仓。这是故意的：
  8% 回撤是按**含浮亏的账户权益**算的，浮盈回吐也算回撤。
- 配置里 `max_open_trades` = 4，每笔 0.5% → 4 笔最多约 2%，3% 的上限这时不会起作用。
  想让 3% 上限起作用，回测时加 `--max-open-trades 6`（或更多）。两者谁先到就按谁。

#### 1.4 回撤降仓

账户权益（已平仓余额 + 持仓浮动盈亏）比运行以来的最高点低 **4%** 以上时（`dd_throttle_start`），新开仓的风险**减半**（`dd_throttle_mult` = 0.5），
权益回到离最高点 4% 以内后恢复。目的是在接近 8% 红线时自动"踩刹车"。

- 回测里每根 K 线都记一次最高点；实盘重启机器人后，最高点从重启那一刻重新算。
- 想关掉：`dd_throttle_start = 0`。

#### 1.5 止损

- **初始止损** = 入场价 ∓ `stop_atr_mult` × ATR（ATR 取信号 K 线那一根的值）。如果策略有"结构止损"（例如 Donchian 的离场通道）
  而且比 ATR 止损更近，就用更近的那个。初始止损价和 ATR 都存进交易记录，机器人重启后还在。
- **移动止损**（策略自己决定）：Donchian = 离场通道；其他策略可以用"吊灯止损"（持仓以来最高价 − N × 入场 ATR，`trail_atr_mult`，默认关闭）。
  移动止损**只收紧、不放宽**，而且只用**已经收盘**的 K 线计算。
- 币安模拟盘/实盘配置已经开了"交易所挂止损单"（`stoploss_on_exchange`），止损移动时 freqtrade 会自动更新交易所里的止损单。

离场原因对照（回测报告、FreqUI、中文通知里显示的英文代码）：

| 代码 | 意思 | 在哪出现 |
|---|---|---|
| `stop_loss` | 打到初始止损 | 都会 |
| `trailing_stop_loss` | 打到被移动过的止损（Donchian 的离场通道、吊灯止损） | 都会 |
| `exit_signal` / `tsmom_fade` | 策略离场信号（TSMOM：动量消失） | 都会 |
| `et_timeout` | 持仓满规定的 K 线数 | 都会 |
| `et_trail_gap` | 新的移动止损价已经在上一根收盘价的另一侧（规则上已经该走了），开盘立即平仓 | 都会（很少） |
| `et_stop_gap` | 这根 K 线一开盘就跳过了止损价，按开盘价平仓（freqtrade 回测默认会假装在止损价成交，那样太乐观） | 只在回测 |
| `et_stop_breached` | 止损价没能挂上而价格已经越过，立即平仓（越过盘口 0.5% 挂单，保证成交） | 只在模拟盘/实盘 |
| `et_stop_invalid` | 按实际成交价算不出有效止损，先挂最远止损当保险，再立即平仓 | 只在模拟盘/实盘 |

#### 1.6 只在信号 K 线刚收盘时入场

回测只会在"信号 K 线收盘后的下一根开盘"入场。实盘默认会在整根 K 线期间（日线 = 一整天）一直按这个信号入场，回测里没有这些交易。
所以设了 `ignore_buying_expired_candle_after = 600`：信号 K 线收盘 10 分钟后就不再入场，和回测口径一致（同 BigTrendShort）。

#### 1.7 参数速查

这些参数是策略类的属性，配置文件改不了。推荐新建一个小文件继承原策略来改（和 `docs/strategies.md` 1.9 节一样）：

```python
from DonchianTrend import DonchianTrend

class DonchianTrendRisk03(DonchianTrend):
    risk_per_trade = 0.003      # 每笔最多亏 0.3%
```

| 参数 | 默认 | 作用 |
|---|---|---|
| `risk_per_trade` | 0.005 | 每笔打到止损亏总资金的比例 |
| `max_portfolio_risk` | 0.03 | 所有持仓"打到止损还会亏多少"的合计上限 |
| `dd_throttle_start` / `dd_throttle_mult` | 0.04 / 0.5 | 回撤超过 4% 后新仓风险减半；0 = 关闭 |
| `max_leverage_param` | 2.0 | 杠杆（最终不超过 5） |
| `stoploss` | −0.50 | freqtrade 的兜底止损（账户口径 = 价格 25% × 2 倍）。改杠杆时同步改成 −(0.25 × 杠杆) |
| `max_stop_distance` | 0.25 | 止损最远距离（价格比例） |
| `stop_atr_mult` | 各策略不同 | 初始止损的 ATR 倍数 |
| `trail_atr_mult` | 0（关） | 吊灯止损的 ATR 倍数 |
| `max_hold_candles` | 0（不限） | 持仓超时（根 K 线） |
| `enable_long` / `enable_short` | True / True | 方向开关 |

> 注意：`risk_per_trade` 不是 hyperopt 参数，不要拿它去"优化"。它是"放大/缩小"整条资金曲线的旋钮：
> 先在训练段确认策略本身有优势（盈亏因子、Sharpe），再按"验证段回撤 ≤ 6%（留余量）"决定它取多大。

### 趋势类 2. DonchianTrend（唐奇安通道突破，多空双向）

**思路**：这就是著名的"海龟交易法"（1980 年代 Richard Dennis 教给学员的规则）的简化版。价格创出 55 天新高说明可能有一段新趋势，
跟进做多；价格回落到 20 天新低说明趋势结束，离场。做空完全对称。

**规则**（逐根已收盘 K 线，没有未来函数）：

| 项目 | 做多 | 做空 |
|---|---|---|
| 入场 | 收盘价 > 前 `entry_period`（55）根 K 线的最高价（不含当根） | 收盘价 < 前 55 根的最低价 |
| 趋势过滤 | 日线收盘在日线 EMA200 上方 | 日线收盘在日线 EMA200 下方 |
| 可选 BTC 过滤（`use_btc_filter`，默认关） | BTC 日线也在 EMA200 上方 | BTC 日线也在 EMA200 下方 |
| 初始止损 | 入场价 − `stop_atr_mult`（2）× ATR20，和离场通道取更近的 | 入场价 + 2 × ATR20 |
| 离场 | 价格碰到最近 `exit_period`（20）根 K 线的最低价 | 碰到最近 20 根的最高价 |

- 离场通道挂成**移动止损**：每根 K 线收盘后更新一次，价格一碰到就走（和海龟原版一样是"碰到就走"，不是"收盘跌破才走"）。
  通道只会往有利方向移动，所以赚钱的单子会一路跟着趋势，直到趋势结束。报告里这类离场显示为 `trailing_stop_loss`。
- 4 小时版：回测时加 `--timeframe 4h`。参数单位是"根 K 线"，4h 的 55 根 ≈ 9 天，**是另一套系统，要单独验证**；
  趋势过滤仍然用日线 EMA200（用 freqtrade 官方的 `merge_informative_pair` 合并，日线收盘后才可见）。

**为什么可能有效**：

- 趋势跟踪是有最长历史证据的策略之一，在商品期货、外汇、股指上几十年都有效（例如 Hurst、Ooi、Pedersen 的百年趋势研究）。
- 加密货币的特点正好适合：涨跌都很猛、经常出现几周到几个月的单边行情。已有研究在加密货币上测试唐奇安突破，结论是长期有效、主要靠少数大赚的单子。
- 赔率结构：胜率通常只有 30% 到 40%，但赚的时候赚得多（让利润奔跑），亏的时候只亏 0.5%（截断亏损）。

**参数**（只有 3 个可以 hyperopt，只在训练段调）：

| 参数 | 默认 | 可调范围 | 空间 | 含义 |
|---|---|---|---|---|
| `entry_period` | 55 | 20 – 80 | buy | 入场突破看多少根 K 线 |
| `exit_period` | 20 | 10 – 30 | sell | 离场通道看多少根 K 线 |
| `stop_atr_mult` | 2.0 | 1.5 – 3.5 | sell | 初始止损几倍 ATR |
| `atr_period` | 20 | 不调 | | 海龟的 N |
| `trend_ema_period` | 200 | 不调 | | 趋势过滤 |
| `use_btc_filter` | False | 不调 | | BTC 大盘过滤 |

**风险**：

- **震荡市会连续小亏**。没有趋势的时候，假突破一个接一个，每次亏 0.5%。连亏 10 次以上很正常，8% 的回撤红线主要就是被这种情况威胁。
  回撤降仓（1.4 节）和热度上限（1.3 节）就是为这个准备的。
- 利润集中在少数几笔：如果某一年恰好没有大趋势，全年可能是亏的。验证段要足够长（至少 6 到 12 个月）。
- 离场通道离价格比较远（20 天），趋势结束时会吐回一部分利润，这部分也算在含浮亏回撤里。
- **资金费**：单子一拿就是几周，牛市里做多每 8 小时要付资金费，一年可能吃掉 10% 以上的名义收益。OKX 只有最近约 3 个月的资金费历史，
  更早的回测按 0 计算，结果会**偏乐观**。`make research` 的结果表里有"样本外扣资金费"列（按每 8 小时 0.01% 估算没有数据那段的资金费），
  样本外只是小赚的要看这一列。上实盘前要用币安数据复核。
- 交易数可能偏少（日线，20 个币，2 年大约几十到一百多笔），统计上要谨慎。

**回测命令**：

```bash
make backtest ARGS="--strategies DonchianTrend --detail 1h --fee 0.0007"
make backtest ARGS="--strategies DonchianTrend --timeframes 4h --detail 1h --fee 0.0007"    # 4 小时版
make backtest ARGS="--strategies DonchianTrend --max-open-trades 6 --fee 0.0007"            # 让 3% 热度上限起作用
```

### 趋势类 3. TsmomTrend（时间序列动量，多空双向）

**思路**：每天收盘问一句"这个币最近是涨还是跌、涨跌得明不明显？"明显上涨就持有多单，明显下跌就持有空单，不明显就空仓。
这就是学术界的"时间序列动量"（Moskowitz、Ooi、Pedersen 2012 年的论文），很多管理期货基金（CTA）用的就是它的变体。

**怎么算**（逐根已收盘 K 线）：

```
z(k)  = ln(今天收盘 ÷ k 天前收盘) ÷ (日波动率 × √k)        ← 这 k 天的涨跌相当于"几个标准差"
分数  = [ z(L) + z(2L) + z(4L) ] ÷ 3                        ← L 默认 20，即同时看 20、40、80 天
日波动率 = 最近 30 天日收益率（对数）的标准差
```

| 项目 | 做多 | 做空 |
|---|---|---|
| 入场 | 分数 > `entry_z`（0.75） | 分数 < −0.75 |
| 波动率过滤 | 最近 10 天波动率 ÷ 最近 90 天波动率 ≤ 2 才开新仓 | 同左 |
| 离场 | 分数跌回 0 以下（动量消失） | 分数回到 0 以上 |
| 止损 | 入场价 − `stop_atr_mult`（3）× ATR20，只防极端行情 | 入场价 + 3 × ATR20 |

- 同时看 3 个长度再取平均，是为了**不赌某一个参数**：只用 20 天容易被噪音骗，只用 80 天反应太慢，平均起来更稳。
- 入场门槛 0.75、离场门槛 0，中间留了一段"缓冲"，避免分数在门槛附近来回抖动时频繁开平仓。
- 信号每天收盘重算：只要分数还在门槛外就继续拿，分数回到 0 就平，效果接近"每天调仓"。被止损后如果信号还在，下一天会重新入场。
- 仓位天然和波动率成反比（止损 = 3 倍 ATR，波动越大仓位越小），相当于 TSMOM 论文里的"按波动率定仓"。

**为什么可能有效**：

- 时间序列动量在几十个市场、上百年的数据里都存在，常见解释是投资者对新信息反应不足、然后又追涨杀跌。
- 加密货币上的研究（例如 Liu & Tsyvinski 2021）发现动量效应很强，1 到 4 周的回看最明显，所以默认 L = 20 天，并同时看到 80 天。
- 波动率过滤的依据：动量策略最大的亏损（"动量崩溃"）通常出现在暴跌后突然暴力反弹的时候，那时短期波动率会远高于长期波动率。

**参数**（3 个可以 hyperopt，只在训练段调）：

| 参数 | 默认 | 可调范围 | 空间 | 含义 |
|---|---|---|---|---|
| `mom_lookback` | 20 | 10 – 40 | buy | 最短回看天数 L（同时看 L、2L、4L） |
| `entry_z` | 0.75 | 0.3 – 1.5 | buy | 入场门槛（几个标准差） |
| `stop_atr_mult` | 3.0 | 2.0 – 4.0 | sell | 止损几倍 ATR |
| `exit_z` | 0 | 不调 | | 离场门槛 |
| `vol_ratio_max` | 2.0 | 不调 | | 波动率过滤 |
| `trail_atr_mult` | 0（关） | 不调 | | 想限制浮盈回吐可以试 3（吊灯止损），算一个新策略，要重新验证 |

**风险**：

- **趋势反转时反应慢**：分数要回到 0 才离场，大涨之后的急跌可能吐回不少浮盈（算在含浮亏回撤里）。热度上限会因此少开新仓。
- 和 Donchian 一样怕震荡市；而且币和币之间高度相关，往往是"一起做多、一起止损"。
- 资金费问题同 Donchian（持仓时间更长，影响更大）。
- 回看最长 160 天，预热 200 根日线，回测开始日期会比数据开始晚约 200 天。

**回测命令**：

```bash
make backtest ARGS="--strategies TsmomTrend --detail 1h --fee 0.0007"
```

### 趋势类 4. BigTrendBoth（BigTrendShort 的多空版 + 大盘状态过滤）

**思路**：BigTrendShort 在 11 月 OKX 回测里是唯一通过 8% 的（+2.43%，盈亏因子 1.16，回撤 7.34%），但只做空，
而且 6 月体检的"做空优势"很大一部分是熊市带来的。BigTrendBoth 保留它的信号原样不动，补上**对称的做多信号**，
再加一个"大盘状态"开关：**牛市只做多，熊市只做空**。

**规则**：

| 项目 | 做多 | 做空（= BigTrendShort） |
|---|---|---|
| 信号 | 一根阳线同时涨穿 EMA7/20/60/100/200 里至少 3 条 | 一根阴线同时跌穿至少 3 条 |
| MACD 确认 | MACD > 信号线，柱体 > 0 且继续放大 | MACD < 信号线，柱体 < 0 且继续放大 |
| 冷却 | 同币同方向 6 根 K 线内只算一次 | 同左 |
| 多周期过滤 | 日线/4h/1h 强烈逆势不开、偏逆势仓位减半（同 BigTrendShort，Rust `mtf.rs`） | 同左 |
| **大盘状态（新增）** | BTC 日线收盘 > BTC EMA200，**并且**这个币自己的收盘 > 它的 EMA200 | BTC 日线 < EMA200，并且这个币 < 它的 EMA200 |
| 止损 | 入场价 − `stop_atr_mult`（3）× ATR14 | 入场价 + 3 × ATR14 |
| 出场 | 持满 `max_hold_candles`（13）根日线，或打到止损 | 同左 |

信号的判断代码和 BigTrendShort 逐行对应（指标函数直接用 `rust_port_common.py` 里的同一份），BigTrendShort 本身没有改动。

**和 BigTrendShort 的区别**：

| 项目 | BigTrendShort | BigTrendBoth |
|---|---|---|
| 方向 | 只做空 | 多 + 空 |
| 大盘过滤 | 无 | BTC 和本币都要在 EMA200 同一侧 |
| 止损 | 兜底 20%（Rust 原版没有止损） | 3 × ATR14（= BigTrendShort 的可选 `stop_mode = "atr"`） |
| 每笔风险 | 1% | 0.5% |
| 杠杆 | 3 倍 | 2 倍 |
| 组合热度 / 回撤降仓 | 无 | 3% / 4% 后减半 |

**为什么可能有效**：

- 一根 K 线同时穿过多条均线，说明短、中、长期的平均成本被一次性突破，常常是新趋势的开始；MACD 确认动能。
- 6 月体检里 BigTrend 做多端是亏的，但那 90 天是下跌行情。加了"只在牛市做多"以后，做多信号只会出现在有利的环境里；
  同理，做空也只在熊市做，避免牛市里逆势做空。
- 出场规则不变（13 天），只改了止损和仓位，信号部分没有新增可调参数，过拟合的空间很小。

**参数**（2 个可以 hyperopt，都只影响出场）：

| 参数 | 默认 | 可调范围 | 空间 | 含义 |
|---|---|---|---|---|
| `stop_atr_mult` | 3.0 | 2.0 – 5.0 | sell | 止损几倍 ATR14 |
| `max_hold_candles` | 13 | 8 – 20 | sell | 持有几根日线后平仓（13 = Rust 的 12 天 + 1 根） |
| `min_emas_crossed` / `dedup_bars` | 3 / 6 | 不调 | | Rust 原值 |
| `regime_ema_period` | 200 | 不调 | | BTC 大盘均线 |
| `require_pair_regime` | True | 不调 | | 是否同时要求本币在 EMA200 同一侧 |

**风险**：

- 大盘状态切换的时候（BTC 在 EMA200 附近来回穿），两个方向都可能刚开仓就遇到反转。
- 加了过滤以后交易数会变少（BigTrendShort 2 年 69 笔），可能不到 30 笔，统计上不可靠。
- 只看 BTC 一个币判断大盘，山寨币自己走独立行情时会错过（所以同时要求本币在 EMA200 同一侧）。
- 需要 1d、4h、1h 三个周期的数据（多周期过滤用），和 BigTrendShort 一样。

**回测命令**：

```bash
make backtest ARGS="--strategies 'BigTrendShort BigTrendBoth' --detail 1h --fee 0.0007"    # 和原版放在一起对比
```

### 趋势类 5. 防过拟合：怎么调参、怎么验证

1. **先用默认参数**跑训练段和验证段。默认值都是经典值，不是在这份数据上挑的。如果默认参数在训练段都不赚钱，就不要靠调参"救"它。
2. hyperopt **只在训练段**跑，例如：

   ```bash
   .venv/bin/freqtrade hyperopt --config configs/config.okx-backtest.json --strategy DonchianTrend \
       --spaces buy sell --hyperopt-loss SharpeHyperOptLossDaily -e 200 --timerange 20240101-20250701
   ```

   - 需要 hyperopt 依赖：`requirements.txt` 现在是 `freqtrade[hyperopt]==2026.10`，以前建的 .venv 补装一次 `.venv/bin/pip install -r requirements.txt`
     （不装会报 `No module named 'filelock'`；官方 Docker 镜像自带）。
   - hyperopt 跑完会自动把最优参数写到策略旁边的 `DonchianTrend.json`，之后的回测都会**自动读取**它。
     想回到默认参数就删掉这个 json。不想让它自动写，加 `--disable-param-export`。
3. **看邻居，不看第一名**：最优参数附近（例如 entry_period 50 / 55 / 60）的结果应该都差不多。
   如果只有某一个值特别好、旁边都很差，那是运气，不要用。
4. 验证段（例如 2025-07 以后）**只回测、不改参数**。训练段和验证段都要满足：总收益 > 0、盈亏因子 > 1.2、两种回撤都 ≤ 8%（建议留余量 ≤ 6%）、交易数 ≥ 30。
5. 回撤离 8% 还远、但收益太小（例如 BigTrendShort 2 年 +2.4%）时，可以在**训练段**按回撤反推加大 `risk_per_trade`，再到验证段确认回撤仍 ≤ 6%。
6. 三个趋势策略彼此高度相关（都是趋势跟踪），**不要**把它们当成三个独立的策略同时实盘，那样风险会叠加。

### 趋势类 6. 合成数据自检（2026-11-06，只看"能不能跑"）

用 `scripts/ft_offline.py` + `configs/config.synthetic-test.json` 离线跑过：

- 三个策略都能正常回测、做多做空都有、杠杆 2 倍、止损和仓位按设计生效（逐笔核对过：初始止损价 = 入场价 ∓ N × ATR，打到止损每笔亏约总资金 0.47%）；

  TsmomTrend 20 笔里有 1 笔"入场偏差"、没有任何指标列被标记：查过是 freqtrade 回测在数据最后一根 K 线开盘价等于最低价时，
  强制平仓单没成交、这笔交易被丢掉，不是策略用了未来数据。

### 非趋势类 1. 一页看懂

| 策略类名 | 一句话逻辑 | 周期 | 方向 | 止损 | 止盈 / 离场 | 可调参数 | 需要的数据 |
|---|---|---|---|---|---|---|---|
| `RangeMeanReversion` | 没有趋势时，价格冲出布林带、RSI 到极值，就反向做，等它回到中轨 | 1h（可 4h） | 多 + 空 | 1.5 倍 ATR（很近） | 回到布林中轨 / 持满 24 根 | 4 个 | 1h + 4h（跑 4h 时要 1d） |
| `VolSqueezeBreakout` | 价格窄幅横盘（布林带缩进肯特纳通道）后，第一次放量冲出横盘区间就跟 | 1h（可 4h） | 多 + 空，只顺日线方向 | 2 倍 ATR 和横盘区间另一侧，取更近的 | 移动止损 3 倍 ATR / 跌回中轨 / 持满 72 根 | 4 个 | 1h（或 4h）+ 1d |

**先读这三条：**

1. **三个策略都还没有真实结果。** 默认参数是按常识事先定好的，没有用任何行情数据调过。

2. **FundingContrarian 现在没法正经评估。** OKX 只给最近约 3 个月的资金费率历史，
   2024-01 ~ 2026-11 的回测里，它只会在最后约 3 个月开仓，样本太少，也分不出训练段和验证段。
   它现在只适合"观察"，要先把资金费率数据攒够（见「非趋势类 5.2」）。
3. **1h 策略交易次数多，对手续费更敏感。** 一定要再加一次 `--fee 0.0007` 做压力测试（「非趋势类 6」），
   手续费稍微高一点就不赚钱的策略，实盘大概率也不赚钱。

### 非趋势类 2. 三个策略共用的规则

三个策略都用第二步新写的共用风控 `user_data/strategies/easytrade_risk.py`（`EasyTradeRiskMixin`），
规则和趋势类完全一样（详细说明见本文档「趋势类 1. 共用风控」）。这里只列要点：

| 项目 | 规则 |
|---|---|
| 杠杆 | 默认 **2 倍**；代码里写死不超过 **5 倍**，参数改不过它。逐仓 |
| 每笔开多少 | 按止损距离算：**打到止损大约亏总资金的 0.5%**（1000 USDT 时约 5 USDT）。止损越近，仓位越大，但有上限 |
| 组合上限 | 所有持仓"从现价打到各自止损还会亏多少"加起来 ≤ 总资金的 **3%**，超过就不开新仓 |
| 回撤降仓 | 账户权益（含浮亏）比最高点低 4% 以后，新仓的风险减半 |
| 入场时机 | 只看**已收盘**的 K 线。信号 K 线收盘后，在下一根开盘入场；实盘只在收盘后 10 分钟内入场，过时不追 |
| 止损执行 | 止损价成交时就算好、存进交易记录，之后只收紧不放宽；实盘止损挂不上时立即平仓 |
| 离场成交 | 信号类离场（回到中轨、突破失败、费率正常）都是"收盘确认，下一根开盘平仓"，回测和实盘口径一致 |
| 同时持仓 | 由配置里的 `max_open_trades` 决定（`config.okx-backtest.json` 是 4，`make research` 用的 `config.okx-research.json` 是 5） |

另外三个策略各自带了**保护机制**（freqtrade 的 protections，`make backtest` 默认会打开）：

- 冷却：同一个币平仓后，等 2 根（FundingContrarian 是 4 根）K 线才能再开。
- 连续止损暂停（RangeMeanReversion、FundingContrarian）：同一个币 48 根 K 线内被止损 2 次，这个币暂停 24 根。
  连续止损通常说明行情性质变了（例如震荡变成了趋势）。

### 非趋势类 3. RangeMeanReversion（震荡均值回归）

**想法：** 行情没有方向、来回震荡时，价格冲出布林带外沿、RSI 到极值，往往会回到中间。
最大的风险是"以为是震荡，其实是新趋势刚开始"，所以用两层"没有趋势"过滤，加上很近的止损和时间止损：错了就马上认。

**入场（全部满足才开）：**

| 条件 | 做多 | 做空 |
|---|---|---|
| 价格到极值 | 收盘价 < 布林下轨（20 根，`bb_std` 倍标准差，默认 2） | 收盘价 > 布林上轨 |
| RSI 到极值 | RSI14 < `rsi_extreme`（默认 30） | RSI14 > 100 − `rsi_extreme`（默认 70） |
| 本周期没有趋势 | ADX14 < `adx_max`（默认 22） | 同左 |
| 大一级周期走平 | 1h 策略看 4h（4h 策略看 1d）：ADX14 < 25，而且 EMA50 最近 6 根的变化不到 1 个 ATR | 同左 |
| 波动没有突然放大 | ATR14 ÷ 最近 100 根平均真实波幅 ≤ 1.5（刚放量突破、急涨急跌时不接飞刀） | 同左 |

**出场：** 收盘价回到布林中轨就平（这是主要的止盈）；打到止损（入场价 ∓ `stop_atr_mult` × ATR14，默认 1.5 倍）；
持满 24 根 K 线（1h 策略 = 1 天）还没回到中轨也平。

**可调参数（只在训练段调，验证段不改）：**

| 参数 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `bb_std` | 2.0 | 1.8 ~ 2.6 | 布林带宽度。越大，信号越少、越极端 |
| `rsi_extreme` | 30 | 20 ~ 35 | RSI 极值。越小，信号越少 |
| `adx_max` | 22 | 15 ~ 30 | 本周期 ADX 上限。越小，越只做"很平"的行情 |
| `stop_atr_mult` | 1.5 | 1.0 ~ 2.5 | 止损距离（几倍 ATR） |

其余阈值（4h 的 ADX 25、斜率 1 个 ATR、波动比 1.5、时间止损 24 根）是固定的常识值，不调。

**适合 / 不适合：** 适合横盘、来回扫的行情；单边大涨大跌时，过滤器会让它基本不开仓。
最怕的是全市场一起急跌：很多币同时碰到下轨、同时做多、同时止损。组合 3% 上限就是为这种情况准备的。

### 非趋势类 4. VolSqueezeBreakout（波动收缩后突破）

**想法：** 波动率有"收缩 → 扩张"的规律。价格窄幅横盘一段时间后，第一次**放量**冲出横盘区间，往往会走出一段。
没放量的突破、已经冲得太远的突破都不追。

**入场（全部满足才开）：**

| 条件 | 做多 | 做空 |
|---|---|---|
| 之前有收缩 | 信号 K 线之前的 3 根里，布林带（20，2 倍）曾经**连续至少 6 根**整个缩在肯特纳通道（EMA20 ± 1.5 × ATR20）里面 | 同左 |
| 突破横盘区间 | 收盘价 > 前 `range_period` 根（默认 20）的最高价，而且收阳 | 收盘价 < 前 `range_period` 根的最低价，而且收阴 |
| 放量 | 本根成交量 ÷ 前 50 根成交量的中位数 ≥ `vol_ratio_min`（默认 1.5） | 同左 |
| 不追太远 | 收盘价离区间边沿不超过 1.5 个 ATR14 | 同左 |
| 顺日线方向 | 上一根已收盘的日线在日线 EMA50 上方 | 在日线 EMA50 下方 |

**关于成交量：** 这里**只用比值**（同一个币自己和自己比），不用任何"成交量要大于多少"的绝对门槛。
所以成交量的单位是张数、币数还是 USDT 都没关系，互相抵消（OKX 成交量单位的说明见 `docs/okx-volume-units.md`）。

**出场：**

- 止损：入场价 ∓ `stop_atr_mult` × ATR14（默认 2 倍），和横盘区间的另一侧比，取离入场价更近的那个。
- 移动止损（吊灯止损）：持仓以来的最高价（做空 = 最低价）退 `trail_atr_mult` × 入场时 ATR（默认 3 倍），只收紧。
- 突破失败：收盘价跌回布林中轨（SMA20）另一侧，下一根开盘平仓。
- 持满 72 根 K 线（1h = 3 天，4h = 12 天）平仓。

**可调参数：**

| 参数 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `range_period` | 20 | 12 ~ 40 | 横盘区间看多少根 |
| `vol_ratio_min` | 1.5 | 1.2 ~ 3.0 | 放量倍数 |
| `stop_atr_mult` | 2.0 | 1.5 ~ 3.0 | 初始止损（几倍 ATR） |
| `trail_atr_mult` | 3.0 | 2.0 ~ 4.5 | 移动止损（几倍 ATR） |

**周期：** 默认 1h。4h 用 `--timeframes 4h`。参数的单位都是"根 K 线"，4h 的 20 根 ≈ 3 天，等于是另一套系统，要单独做一遍训练段 / 验证段。

### 非趋势类 5. FundingContrarian（资金费率反向）

**想法：** 永续合约的资金费率反映多空哪边更拥挤。费率特别高，说明很多人在加杠杆做多；
一旦价格涨不动，多头的止损和爆仓会把价格往下砸。费率特别低（负）则反过来。
这时反向开仓，顺便还能"收"资金费（做空时费率为正，空头收钱）。

**费率怎么算：**

- 每次结算的费率先换算成"**每 8 小时**"口径。OKX 大多数币 8 小时结算一次，但有些币会改成 4 / 2 / 1 小时一次，
  按两次结算的间隔换算，例如 4 小时结算一次的 0.03% 记为 0.06%。
- 取最近 24 小时内各次结算的平均（`fund_avg`），至少要有 2 次结算才算数。
- **中性费率**按 0.01% / 8h 算（OKX、币安多空平衡时的默认费率），"偏离" = `fund_avg` − 0.01%。
- 只用"结算时间 ≤ 这根 K 线开盘时间"的费率：结算以后才知道，比实际能拿到的时间还晚一点，不会用到未来数据。

**入场：**

| 条件 | 做空（多头太挤） | 做多（空头太挤） |
|---|---|---|
| 费率极端 | 偏离 ≥ `fund_extreme`（默认 0.04%，也就是 24 小时平均费率 ≥ 0.05% / 8h），而且最近一次结算的偏离至少是它的一半 | 偏离 ≤ −0.04%（平均费率 ≤ −0.03% / 8h），最近一次结算同样还偏 |
| 之前确实追进去了 | 过去 72 根 K 线（3 天）是涨的 | 过去 72 根是跌的 |
| 动能停滞 | 收盘价跌到 EMA20 下方，而且 EMA20 比 3 根前低 | 收盘价回到 EMA20 上方，而且 EMA20 比 3 根前高 |

**出场：** 最近一次结算的费率回到中性（做空：≤ 0.01%；做多：≥ 0.01%），说明拥挤已经消失，下一根开盘平仓；
止损 1.5 倍 ATR14（严格）；移动止损 2.5 倍 ATR；持满 48 根 K 线（2 天）。

**可调参数：** `fund_extreme`（0.02% ~ 0.10%，默认 0.04%）、`stop_atr_mult`（1.0 ~ 2.5，默认 1.5）、
`trail_atr_mult`（1.5 ~ 4.0，默认 2.5）。**在资金费率数据攒够之前不要调**（原因见「非趋势类 5.2」）。

#### 5.1 没有数据时：一笔都不开（失败即安全）

以下任何一种情况，这根 K 线都**不开仓**，日志里会写明原因：

- 这个币没有资金费率数据，或者读取出错；
- 最近一次结算已经是 12 小时以前（数据断了）；
- 24 小时内不到 2 次结算。

已经持有的仓位如果遇到数据中断，不会因为"没数据"乱平仓，照常由止损、移动止损、超时来管。

**注意：** OKX 回测配置里的 `"futures_funding_rate": 0` 只用来在**算资金费成本**时把缺数据的时间段按 0 处理，
**不会**变成这个策略看到的费率。策略只读磁盘上真实下载到的费率，看到的缺口就是缺口。
回测日志里每个币会打印一行：

```
FundingContrarian BTC/USDT:USDT: 资金费率 276 条 (2026-08-05 ~ 2026-11-04), 覆盖 2200 / 17520 根 K 线; 没覆盖的时间不开仓
```

#### 5.2 OKX 资金费率历史只有约 3 个月

- OKX 的资金费率历史接口**只能查最近约 3 个月**。freqtrade 下载时更早的部分下载不到，这是正常的
  （`scripts/download_okx_data.sh` 和 README 里也写了）。
- 所以 2026-11-06 第一次下载后，VPS 上的资金费率大约只有 **2026-08 ~ 2026-11**。
  用 2024-01 ~ 2026-11 回测时，FundingContrarian **只会在最后约 3 个月开仓**，前面两年多一笔都没有。
- 3 个月里极端费率的次数很少，样本太少，**也分不出训练段和验证段**，任何调参都等于对着答案改题。
  所以：**现在不要 hyperopt 这个策略，只看默认参数的结果，当作"观察"。**

**怎么把数据攒够（推荐，最简单）：**

1. 在 VPS 上**定期运行 `make download`**，建议每周一次，最长不能超过 2 个月一次。
   freqtrade 是增量更新的：每次从本地最后一条接着往后下，**旧数据会保留**。
   只要两次下载的间隔小于 3 个月，资金费率就不会断档，会一直攒下去。
   只想更新资金费率的话，跑 1h 就够：`make download ARGS="--timeframes '1h'"`（合约模式会自动带上资金费率）。
2. **不要**加 `--erase`，也**不要**删除 `user_data/data/okx/`，否则攒的资金费率会一起没了，而且再也下载不回来。
   建议偶尔把 `user_data/data/okx/futures/*-funding_rate.feather` 备份一份。
3. 攒到大约 **9 ~ 12 个月**后，再用 `make research` 分训练段 / 样本外认真评估（方法见「非趋势类 6」）。

**更长历史的其他来源（需要另写导入脚本，现在还没有做）：**

- 币安公开数据站（data.binance.vision）有 U 本位合约每个月的资金费率文件，可以追溯到好几年前。
  币安和 OKX 的费率走势高度相关，但不完全一样，只能当"近似"。美国 VPS 能不能访问这个网站要实际试一下。
- OKX 官网的"历史数据下载"页面可能也提供资金费率文件，需要人工确认有没有、格式是什么。
- 不管用哪个来源，都要转换成 freqtrade 的格式（`user_data/data/okx/futures/<币>_USDT_USDT-1h-funding_rate.feather`，
  两列：`date`、`funding_rate`）才能用。这个导入脚本是后续的待办。
- 以后在允许访问币安的地区直接用币安数据回测时，币安接口本身就能下载完整的资金费率历史，没有 3 个月的限制。

#### 5.3 技术说明：freqtrade 2026.10 里策略怎么读资金费率

这部分写给以后改代码的人，不影响使用。

- 资金费率在 freqtrade 里是一种单独的 K 线类型 `funding_rate`。2026.10 存成每次结算一行，只有两列
  `date`、`funding_rate`（读进来时还会多一个兼容旧版的 `open` 列，值相同）。
  缺的 K 线**不会**被补齐（`ohlcv_fill_up_missing_data` 对资金费率直接跳过）。
- 资金费率的周期由交易所决定：`dp.get_funding_rate_timeframe()`，OKX 和币安在 2026.10 都是 `1h`。
  传了别的周期，freqtrade 会打一条警告并自动改成 1h。
- 读取：`self.dp.get_pair_dataframe(pair, "1h", candle_type="funding_rate")`。
  回测时直接从磁盘读（和回测算资金费用的那份数据是分开加载的，所以 `futures_funding_rate: 0` 不会混进来）；
  实盘时读交易所刷新到的数据，所以策略的 `informative_pairs()` 里返回了 `(币, "1h", "funding_rate")`，
  freqtrade 才会每轮去刷新。
- 没有用 `@informative("1h", candle_type="funding_rate")` 装饰器：它在数据为空时会直接抛错
  （`Informative dataframe ... is empty`），整个策略停掉，做不到"没数据就不开仓"。
- OKX 的资金费率来自 ccxt 的 `fetch_funding_rate_history`，取的是 `realizedRate`（实际结算费率），时间戳是结算时间。

### 非趋势类 6. 怎么验证（防止过拟合）

**目标：** 样本外（验证段）赚钱，而且账户整体回撤（含浮亏）≤ 8%。只在训练段好看的不算。

**正式验证用 `make research`**（README「第 2 步：策略研究」）：它对所有策略用同一套自动切分——
训练段 = 数据的前约 2/3（只有这里可以调参），样本外 = 最后约 1/3（只验证，**不改任何参数**；
看完结果再回去改参数，样本外就作废了），另外还有走步验证。注意：训练段调出的参数从没见过样本外这段，
但走步验证的后几折会用这段时间的数据重新调参，所以"优化参数"那一行的样本外和走步结果**不是两份独立证据**
（"默认参数"那一行不受影响）。下面的手动命令只是抽查用的例子，
日期（以 2025-07-01 为界）和 `make research` 的自动切分不完全相同。

**第 1 步：默认参数，两段各跑一次**（在 VPS 上）：

```bash
make backtest ARGS="--strategies 'RangeMeanReversion VolSqueezeBreakout FundingContrarian' --timerange 20240101-20250701"
make backtest ARGS="--strategies 'RangeMeanReversion VolSqueezeBreakout FundingContrarian' --timerange 20250701-"
# 4h 版本（RangeMeanReversion 和 VolSqueezeBreakout 支持）
make backtest ARGS="--strategies 'RangeMeanReversion VolSqueezeBreakout' --timeframes 4h --timerange 20250701-"
```

**第 2 步：压力测试**（验证段）：

```bash
# 手续费加到每边 0.07%（比 OKX taker 0.05% 高，模拟滑点）
make backtest ARGS="--strategies 'RangeMeanReversion VolSqueezeBreakout' --timerange 20250701- --fee 0.0007"
# 用 5m 模拟 1h K 线内部走势，止损和移动止损判断更准（需要已下载 5m 数据）
make backtest ARGS="--strategies 'RangeMeanReversion VolSqueezeBreakout' --timerange 20250701- --detail 5m"
```

**第 3 步（可选）：只在训练段调参**

```bash
.venv/bin/freqtrade hyperopt --config configs/config.okx-backtest.json --strategy RangeMeanReversion \
    --hyperopt-loss CalmarHyperOptLoss --spaces buy sell --timerange 20240101-20250701 -e 300 --enable-protections
```

调完以后，用调出来的参数在验证段**只跑一次**。另外注意：

- 每个策略只有 3 ~ 4 个参数、范围很窄，是故意的：参数越多，越容易"背答案"。
- 最好的参数落在范围边上（例如 `adx_max` 正好是 30），或者把参数挪一格结果就大变，都说明不稳，不要用。
- 调参后的验证段结果明显不如默认参数，就用默认参数。
- FundingContrarian 现在**不要调**（「非趋势类 5.2」）。
- 开发机上的 venv 没装 hyperopt 依赖（缺 `filelock`、`optuna`），这条命令在开发机上跑不了。
  VPS 上如果也报 "Please ensure that the hyperopt dependencies are installed"，运行 `.venv/bin/pip install -r requirements.txt` 补装（现在 requirements.txt 已经带上 hyperopt 依赖）；Docker 官方镜像自带。

**怎么算"通过"：** 验证段同时满足——

| 指标 | 要求 |
|---|---|
| 回撤（平仓）和 回撤（含浮亏） | 都 ≤ 8%（`check_drawdown.py` 判定，`make backtest` 会自动跑） |
| 总收益 | > 0，而且加 `--fee 0.0007` 后仍然 > 0 |
| 盈亏因子 | ≥ 1.2（1.0 ~ 1.2 太薄，手续费和滑点一变就没了） |
| 交易数 | ≥ 30（太少说明不了问题） |
| 按月看（日志里的月度表） | 不是靠一两个月撑起来的 |
| 训练段 | 也要赚钱。只有验证段好、训练段差，多半是运气 |

**通过以后**也不要直接上实盘：先上模拟盘跑至少 1 ~ 2 个月，对比模拟盘和回测在同一段时间的交易是否一致。

### 非趋势类 7. 合成数据自检结果（2026-11-06，只说明流程跑通，数字没有意义）

开发机连不上 OKX，只能用 `scripts/make_synthetic_data.py` 生成的**随机**行情
（6 个币，2024-11 ~ 2026-11，资金费率只有最近约 92 天）跑了一遍。合成数据里策略不可能有真正的优势，
**收益和回撤数字不能用来评价策略**，这里只看"每一步有没有报错、机制是否按设计工作"。

| 检查 | 结果 |
|---|---|
| 语法 / 导入 / `list-strategies` | 3 个策略都是 OK |
| 回测（1h，默认参数，开保护机制） | RangeMeanReversion 287 笔，VolSqueezeBreakout 214 笔，FundingContrarian 72 笔，都没有报错 |
| 回测（4h） | RangeMeanReversion 52 笔，VolSqueezeBreakout 53 笔，没有报错 |
| 杠杆 | 所有交易都是 2 倍（≤ 5 倍） |
| 仓位 | 打到止损每笔亏约 2 ~ 6 USDT（总资金 1000 USDT 的 0.2% ~ 0.6%），按止损距离定仓正常 |
| 资金费率"没数据不开仓" | FundingContrarian 的 72 笔全部在 2026-08-06 ~ 2026-11-03 之间，正好是有资金费率数据的那段；前面近两年一笔都没有 |
| 资金费率换算 | 单独测过：4 小时结算一次的费率会按 8 小时口径翻倍；24 小时内不到 2 次结算时不算数 |
| 参数边界 | 每个可调参数取最小 / 最大值的所有组合，指标和信号都能正常计算 |
| 未来函数检查（lookahead-analysis） | 3 个策略各 20 个信号，用了未来数据的入场 / 离场信号都是 0 |
| 预热长度检查（recursive-analysis） | 用策略自带的预热长度时，所有指标和更长预热的差别 ≤ 0.03% |
| hyperopt | 开发机的 `.venv` 没装 hyperopt 依赖；临时装上后用 `make research-synthetic` 跑通了整条研究流程（含调参，2026-11-06）。这份合成数据上三个非趋势策略默认参数在训练段都亏损或没有交易，按"训练段不赚钱就不调参"的规则没有调参 |

自检中发现并改掉的一处：RangeMeanReversion 原来用 Wilder 的 ATR100 衡量"慢速波动"，这种指标是递推的，
300 根预热时和"无限长历史"还差约 12%，结果会随回测起点变化。现在改成最近 100 根真实波幅的简单平均，差别降到 0。
